# Site Navigation Audit

Site Navigation works as both a directory and a set of starting points. It already accommodates more than artifact type: visitors can follow a job-search story, explore AI collaboration or choose something playful. Its biggest discovery gap is **moving from a particular work to another work that answers the same question**. A visitor can find the CYOA and Anchorpoint histories under Resident Inventor, but the directory gives them little reason to read those two together. A small number of explicit connections would test whether that gap matters before adding another way to browse the whole site.

## Evidence and scope

The checked-in implementation at `921ee061` defines current behavior. This is a source walkthrough, including local destinations, their front matter and related links. The live Site Navigation page could not be retrieved through web browsing. External destinations were checked separately. The OEI home and About pages and the main Substack profile returned content. The dedicated OEI methodology link, ECH, Lemonade Economy, Inventor’s Lab, the Toddler article, Pantry Behavior, Gumroad and the booking link could not be independently retrieved in this pass. A fetch failure does not establish a broken link. For these, the matrix distinguishes local evidence from the directory's descriptions. No visitor testing or mobile rendering was performed. ## 5. Architecture alternatives

| Criterion | A. Refine the existing taxonomy | B. Add cross-cutting discovery | C. Refine and trial a few related routes |
| --- | --- | --- | --- |
| Visitor comprehension | Familiar categories and more descriptive labels. Direct for named items. | Visitors learn when to use the added layer. Abstract theme labels need examples. | Familiar start, with concrete questions and small link groups using existing patterns. |
| Discoverability | Best for locating one known item, a role or a content type. Limited lateral discovery. | Broadest potential for cross-domain discovery when categories are well maintained. | Helps likely next clicks where there is strong conceptual evidence. Coverage can grow after use is observed. |
| Redundancy | Keeps two views with different jobs. Repeated links remain legible when role is clear. | A theme index would repeat many links and compete with guided cards. | Contextual repetition is a small cost where an explicit connection changes the next step. |
| Cognitive load | Lowest. A few added subheadings or clearer links help scanning. | Highest if visitors face directory, cards, theme browse and Rabbit Hole together. | Moderate if embedded in existing cards or as one or two “related” links at existing decision points. |
| Editorial maintenance | Existing manual model. One audit pass for repeated labels and targets. | A reusable many-to-many registry would need ownership, inclusion rules and review on new work. A static version still needs ongoing curation. | Existing model can carry the trial. Document why each link earns its place and review during content updates. |
| Compatibility | Fits ordinary Jekyll links and responsive markup. | Static theme pages fit the stack. An interactive tag/filter UI would add behavior, state and a separate accessibility review. | Fits existing markup and editorial conventions without a separate interface. |
| Overcomplication risk | Low. Too many new taxonomy subcategories could weaken scanning. | High if the eight provisional concepts become categories or if every work must have a tag. | Low with a strict initial limit. Higher if small experiments accumulate without review. |
| Future inventions | New pages grow their project family, but a novel kind of work may strain existing bins. | Can give an unfamiliar form multiple plausible entries as the body of work grows. | New work has a primary home and can join a curated route once a clear relationship emerges. |

**Preferred direction — C in sequence.** Make A's corrections and label refinements first. Then trial **Same idea, new form** alongside a concrete **Seeing it differently** pairing, integrated into existing paths or related-link positions. These routes can be tested on paper. Hidden work is a strong follow-on if visitors already understand “systems and organizational work” and still miss the household or factory connections. B becomes worthwhile if visitors consistently use several thematic routes or need to browse across relationships beyond the existing guided area.
